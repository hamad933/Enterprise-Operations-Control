# RP02 Visual Convergence

## Governing hierarchy

`RP02-DEC-VIS-002 — ROUTE_RIBBON_PRECISION_AUTHORITY` is the governing visual authority. The accepted `prototypes/rp02-s01/index.html` is the strongest concrete visual/interaction anchor where compatible with current product semantics. Historical R01 styling is not treated as frozen truth.

The product visual character is:

- Spatial Site-to-Action System;
- Precision Editorial Material;
- Focused Authority Layers;
- premium light operational canvas.

## Shared visual rules

### Precision Ledger

Operational information uses disciplined alignment, compact typography, restrained separators, low-shadow surfaces, and fewer framed containers. Summary metrics act as an editorial index rather than a decorative dashboard tile grid. Definition data is grouped as ledger-like facts instead of repeated mini-cards.

### Authority Aperture

Authority/evidence context remains calm when allowed and becomes materially more focused for denied, missing, conflicting, rejected, pending, or overdue states. Visibility never visually implies action, decision, verification, or approval authority.

### Route Ribbon

A route/progression treatment appears only when a real operational journey exists. S01 retains the accepted Site → Signal → Evidence → Verification → Decision → Action → Outcome ribbon. S04/S05 use compact measurement/decision progression because those surfaces genuinely represent ordered operational state. Completed, current, and later stages are visually differentiated.

## Surface composition

- **S01:** remains the accepted concrete anchor; no visual rewrite was required.
- **S02:** retains the dense Work Queue / Focus Task structure with reduced framing. On mobile, the selected Focus Task is prioritized before the long queue while preserving the accepted Grid layout contract.
- **S03:** emphasizes site/asset hierarchy and selected operational context; mobile prioritizes the selected asset and authority context before long ledgers.
- **S04:** emphasizes KPI definition/lineage and measurement progression; charts remain secondary.
- **S05:** emphasizes the selected deviation, authority aperture, and decision progression before the queue on mobile.
- **S06:** emphasizes review authority, evidence, and role separation before the review ledger on mobile.
- **S07:** is chronology-first and uses a full-width audit timeline rather than a repeated sticky inspector composition.
- **S08:** separates application access class from operational authority and prioritizes the selected access profile/context on mobile.

## Responsive hierarchy

Desktop keeps dense operational ledgers with contextual side apertures only where useful. Tablet removes unnecessary sticky pressure and preserves readable ledger density. Mobile does not merely stack the desktop order: selected action/evidence context is moved ahead of long lists where the next operational action depends on that context. Fixed mobile navigation remains available without changing application semantics.

## Corrections made

The convergence pass reduced card repetition, detached hero framing, equal-tile dashboard language, excessive borders/radii/shadows, and generic inspector repetition across S03–S08. It aligned the S03–S08 shell mark/material treatment with S01, strengthened precision-ledger grouping, refined authority emphasis, gave S07 its own audit-first composition, and improved mobile information priority. S01/S02 authority, evidence, closure, rework, and accessibility behavior was not changed.

## Boundary

All values and actions remain synthetic and in-memory. This workstream introduces no framework, runtime dependency, backend, database, production authentication, live integration, persistent upload, release, or deployment behavior.
